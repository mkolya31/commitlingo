# CommitLingo

[English](README.md) | [Русский](README.ru.md)

Многоязычные Conventional Commits для ИИ-агентов разработки. Первый поддерживаемый
агент — Codex.

```text
feat(auth): добавлена авторизация через GitHub
feat(auth): add GitHub authentication
```

CommitLingo изучает реальные изменения, выбирает подходящие тип и область
изменений (scope), затем применяет языковые правила проекта. На русском сообщение
описывает завершённый результат, на английском используется повелительное
наклонение. История помогает выбрать язык, но не определяет грамматику.

## Установка и обновление

Требуются Node.js 22.20 или новее, Git и Codex. npm-пакет подготовлен к выпуску;
следующие команды станут доступны после публикации:

```sh
npx commitlingo-skill
npx commitlingo-skill --global
npx commitlingo-skill update
npx commitlingo-skill update --global
```

Без `--global` установка и обновление выполняются для текущего проекта.
Глобальная установка делает скилл доступным в Codex во всех проектах. Обновление
меняет только CommitLingo в выбранной области установки, сохраняя настройку языка,
пользовательские локали и данные их проверки. CLI устанавливает скилл, а Codex
составляет сообщения и выполняет запрошенные действия с Git. Установщик использует
зафиксированную версию Skills CLI.

Стабильные версии пакета соответствуют стабильным выпускам скилла, привязанным к
конкретному Git-коммиту. При обновлении выбирается последний стабильный выпуск;
предварительные версии не учитываются.

## Использование в Codex

Попросите предложить сообщение или явно создать коммит:

- «Используй CommitLingo, чтобы предложить сообщение коммита».
- «Используй CommitLingo, чтобы сделать коммит с этим изменением».
- «Переключи язык коммитов этого проекта на английский».

Запрос сообщения не добавляет файлы в индекс и не создаёт коммит. При запросе
коммита скилл в первую очередь использует изменения из индекса, сохраняя частичную
индексацию. Если индекс пуст, скилл может подготовить изменения одной явно связанной
задачи; при неоднозначности или наличии несвязанных изменений нужно выбрать состав
коммита. В чистом репозитории скилл не выдумывает сообщение, не спрашивает о языке и
не создаёт пустой коммит.

Настройки проекта хранятся в `.agents/commit-config.json`:

```json
{ "locale": "ru" }
```

Добавьте этот файл в коммит, чтобы закрепить соглашение команды. Настройка не
зависит от глобальной установки скилла и имеет приоритет над историей. Если язык не
сохранён, скилл изучает до 50 коммитов, исключая коммиты слияния и явно
сгенерированные или шаблонные сообщения. Для автоматического выбора нужны как
минимум 5 содержательных сообщений, из которых не менее 80% написаны на одном
языке. Иначе скилл задаёт вопрос; ни английский, ни русский не используются как
запасной вариант.

После сообщения на языке, определённом по истории, скилл явно предлагает сохранить
этот язык или выбрать другой. Предложение повторяется, пока настройка не сохранена.
Перед созданием коммита один вопрос позволяет сохранить настройку и включить её в
коммит, сохранить её вне этого коммита, продолжить без сохранения или выбрать другой
язык. При выборе другого языка сообщение составляется заново до создания коммита.

Скилл учитывает существующие ограничения проекта на тип, scope, регистр и длину, а
также пресеты выпуска. Если доступен локальный commitlint, используется он. Иначе
скилл выполняет базовую проверку и сообщает, если настроенный commitlint не удалось
запустить. Неразрешённый конфликт грамматики с правилами проверки останавливает
создание коммита. Известные ссылки на задачи оформляются по соглашению проекта или
как `Refs: ...`; ссылки, закрывающие задачи, требуют явного намерения их закрыть.

## Добавление языка

Если нужной локали нет, выберите существующую или попросите создать новую.
Англоязычный шаблон записывается в `.agents/commitlingo/locales/<code>.md`.
Переведите и адаптируйте грамматические правила, хорошие примеры и плохие примеры с
исправлениями. Оставьте `locale`, `name` и три заголовка разделов без изменений.
Само наличие черновика не активирует локаль.

Попросите CommitLingo проверить готовую локаль. Скилл проверит структуру и
согласованность, затем запишет SHA-256 проверенного содержимого в
`.agents/commitlingo/locale-reviews.json`. При вычислении хеша окончания строк
приводятся к LF, но все остальные символы, включая пробелы, сохраняются. После
изменения содержимого нужна повторная явно запрошенная проверка. Добавьте в коммит
и локаль, и реестр проверок, чтобы другие участники могли использовать готовую
локаль. Проверка человеком, свободно владеющим языком, остаётся полезной: структура
и хеш не подтверждают качество языка. Локали проекта имеют приоритет над встроенными;
если переопределяющая локаль остаётся черновиком, скилл не переключается незаметно
на встроенную версию.

После успешной проверки скилл предлагает выбрать локаль, а отдельно — отправить её
в проект через PR. Публикация необязательна. Повреждённые данные проверок сохраняются
и исправляются только по явному выбору; неподдерживаемые схемы не заменяются более
старыми версиями. См. [руководство по участию](docs/CONTRIBUTING.md) и
[сценарии ручной проверки](docs/MANUAL_TESTS.md) (на английском).

## Разработка

```sh
npm ci
npm test
npm run check
npm run lint
npm run format:check
```

Автоматические проверки проверяют файлы, инварианты обработки данных и установщик.
Поведение и качество языка оцениваются отдельно с помощью воспроизводимых сценариев
Codex; ключ API не требуется. CI запускает автоматические проверки в Windows, macOS
и Linux. Локальный CLI для разработки доступен через `node bin/cli.js --help`.

Проект использует OpenSpec (`spec-driven`). Актуальные спецификации находятся в
`openspec/specs/`. Выполненный план реализации сохранён в архиве
`openspec/changes/archive/2026-11-18-create-commitlingo-skill/`; для будущих изменений
используйте скиллы OpenSpec из репозитория. Если CLI не установлен глобально:

```sh
npx --yes @fission-ai/openspec@2.1.0 validate --all
```

## Происхождение и лицензия

Общий подход адаптирован из `conventional-commit-message` проекта Conventional
Changelog. До адаптации исходные файлы были добавлены отдельным коммитом без
изменений, поэтому полную разницу можно посмотреть через Git.
[Сведения об исходном проекте и команды сравнения](skills/commitlingo/UPSTREAM.md)
указывают точную ревизию, исходный коммит, автора и сохранённые уведомления MIT/ISC.
Собственные доработки CommitLingo распространяются по [лицензии MIT](LICENSE).
