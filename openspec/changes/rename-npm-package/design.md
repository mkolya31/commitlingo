# Design

## Context

Причина изменения описана в proposal.md. `lib/installer.js` содержит отдельные литералы имени npm-пакета, registry URL, проверки npm/source metadata и аргументы делегирования через npm exec. `package.json` предоставляет executable `commitlingo`. Тестовые метаданные также используют старое имя. Имя скилла в Skills API, исходный репозиторий и каталоги данных относятся к другой идентичности.

## Goals / Non-Goals

**Goals:** исключить рассогласование между первым опубликованным пакетом, registry lookup и executable при обновлении; сохранить установку существующего скилла и пользовательские данные.

**Non-Goals:** автоматизация публикации, миграция опубликованного старого пакета, изменение поведения формирования коммитов, переименование репозитория и исторических записей.

## Decisions

- npm package и единственный bin получают имя `commitlingo-skill`. Альтернатива — оставить bin `commitlingo` — сохраняла бы короткую команду, но усложняла бы сопоставление пакета, справки и делегирования. Старый bin alias не нужен до первого релиза.
- В установщике выделить константу имени npm-пакета и использовать её для URL, проверок metadata и package selector при делегировании. Исполняемая команда должна соответствовать новому bin. Имена скилла `commitlingo`, source repository `mkolya31/commitlingo` и пользовательские пути не заменять глобальным поиском.
- Сохранить `0.1.0`, закреплённую зависимость Skills API и SHA-проверки. Отклонение публикации старого имени не требует повышения версии нового пакета.
- Актуализировать README, инструкции выпуска, CLI fixtures и проверки упаковки. Архивы OpenSpec и журнал прошлой проверки сохраняют исторические команды; основной spec обновляется через delta при sync/archive.
- Проверять установку на контролируемых метаданных и временных репозиториях; дополнительно проверить bin и состав `npm pack --dry-run`. Не требовать публикации для завершения реализации.

## Risks / Trade-offs

- [Новое имя тоже может отклонить npm] → не обещать доступность по результату npm view; фактическая публикация является отдельным действием.
- [Частичная замена сломает update] → проверить полный путь: registry URL, проверка имён, точный package selector, executable и обе области.
- [Массовая замена переименует скилл или настройки] → отдельно проверять сохранение `skills: ['commitlingo']`, source repository и пользовательских файлов в существующих интеграционных тестах.

## Migration Plan

Внести согласованные изменения, выполнить проверки и проверить CI на поддерживаемых ОС. Закоммитить и отправить исходники до отдельной публикации `commitlingo-skill@0.1.0`, чтобы gitHead был доступен в GitHub. После публикации отдельно проверить реальную установку в временном проекте. До публикации откат — обычный revert; после публикации исправления выпускаются новой версией, переиспользование опубликованной версии не предполагается.
