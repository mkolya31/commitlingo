# Spec Delta

## MODIFIED Requirements

### Requirement: Локальная установка по умолчанию
Команда `npx commitlingo-skill` SHALL устанавливать скилл CommitLingo для Codex только в текущий проект. Глобальная установка SHALL требовать явного флага `--global`.

#### Scenario: Установка без параметров
- **WHEN** пользователь запускает `npx commitlingo-skill` в проекте
- **THEN** скилл устанавливается локально для этого проекта без глобальной установки

#### Scenario: Явная глобальная установка
- **WHEN** пользователь запускает `npx commitlingo-skill --global`
- **THEN** скилл устанавливается глобально для Codex


### Requirement: Обновление имеет отдельную команду и область
Команда `npx commitlingo-skill update` SHALL обновлять только CommitLingo в текущем проекте. Команда `npx commitlingo-skill update --global` SHALL обновлять только глобальную установку CommitLingo. Другие скиллы и установка в другой области SHALL оставаться без изменений.

#### Scenario: Локальное обновление
- **WHEN** установлены локальный и глобальный CommitLingo и другие скиллы, а пользователь запускает `npx commitlingo-skill update`
- **THEN** обновляется только CommitLingo текущего проекта, глобальная установка и другие скиллы не изменяются

#### Scenario: Глобальное обновление
- **WHEN** пользователь запускает `npx commitlingo-skill update --global`
- **THEN** обновляется только глобальный CommitLingo без изменения локальной установки и других скиллов


### Requirement: Версии пакета и скилла согласованы
Каждая версия npm-пакета `commitlingo-skill` SHALL устанавливать соответствующую версию скилла из стабильного релиза, привязанного к конкретному Git commit SHA. Повторная установка этой версии SHALL воспроизводить релизное содержимое независимо от последующих изменений основной ветки.

#### Scenario: Установка известного релиза
- **WHEN** устанавливается определённая стабильная версия npm-пакета CommitLingo
- **THEN** устанавливается соответствующая версия скилла из зафиксированного релизного Git SHA

#### Scenario: Основная ветка изменилась
- **WHEN** после выпуска релиза в основной ветке появились новые изменения и пользователь повторно устанавливает прежнюю версию пакета
- **THEN** устанавливается содержимое прежнего релиза, а не новое содержимое основной ветки


### Requirement: Обновление выбирает последний стабильный релиз
Команда `update` SHALL переводить установку на последний стабильный релиз npm-пакета `commitlingo-skill`, сохраняя согласованность целевых версий npm-пакета и скилла. Предварительные версии SHALL не устанавливаться автоматически.

#### Scenario: Доступны stable и prerelease
- **WHEN** опубликован стабильный релиз и более новая предварительная версия, а пользователь запускает `update`
- **THEN** целевой версией становится последний стабильный релиз без автоматической установки предварительной версии

#### Scenario: Обновление запускается старой обёрткой
- **WHEN** установленный скилл и запускающая обновление обёртка относятся к старому релизу, а доступен новый стабильный релиз
- **THEN** обновление приводит к согласованной целевой паре версий пакета и скилла нового стабильного релиза, сохраняя выбранную область и пользовательские файлы

## ADDED Requirements

### Requirement: Публичное имя пакета и идентичность скилла
Пакет SHALL публиковаться под именем `commitlingo-skill` и предоставлять одноимённый executable. Установка SHALL сохранять имя скилла `commitlingo` и его проектные пути. Справка и диагностика SHALL указывать команды нового npm-пакета.

#### Scenario: Имена пакета и установленного скилла
- **WHEN** пользователь запускает `npx commitlingo-skill`
- **THEN** устанавливается скилл `commitlingo` для Codex, без создания скилла `commitlingo-skill`

#### Scenario: Справка CLI
- **WHEN** пользователь запускает `npx commitlingo-skill --help`
- **THEN** справка показывает установку и обновление через `npx commitlingo-skill` с поддержкой `--global`

### Requirement: Метаданные и обновление используют имя npm-пакета
Получение релиза и выбор обновления SHALL обращаться к `commitlingo-skill` в npm. Установщик SHALL проверять это имя в метаданных npm и исходного коммита. Делегирование другой версии SHALL запускать executable `commitlingo-skill` из точной версии этого пакета с сохранением области установки.

#### Scenario: Метаданные другого пакета
- **WHEN** метаданные npm или исходного коммита содержат имя `commitlingo` вместо `commitlingo-skill`
- **THEN** установщик отказывается от установки до изменения установленного скилла

#### Scenario: Обновление запускается старой версией нового пакета
- **WHEN** `npx commitlingo-skill update --global` обнаруживает более новую стабильную версию
- **THEN** запускается точная целевая версия пакета `commitlingo-skill` с executable `commitlingo-skill` и глобальной областью установки
