# Proposal

## Why

При генерации коммитов агентам приходится повторять требования к языку, грамматике и Conventional Commits. CommitLingo объединяет содержательный анализ изменений с правилами локали и сохраняемым соглашением команды: русский описывает завершённый результат, английский использует imperative.

## What Changes

- Создать Codex Skill на основе `conventional-commit-message` проекта Conventional Changelog с атрибуцией и фиксацией исходной ревизии.
- До адаптации скопировать исходный скилл без изменений и обязательно создать отдельный коммит импорта с указанием upstream SHA и сохранением лицензионных уведомлений. Этот коммит служит точкой сравнения исходника с последующей реализацией CommitLingo; адаптация начинается только после его успешного создания и проверки.
- Разделить общий анализ diff, `type`, `scope`, breaking changes и ссылок на задачи от грамматических правил локалей; поставить `ru` и `en`.
- Поддержать генерацию сообщения и выполнение коммита по явной просьбе, используя staged-набор либо самостоятельно подготавливая однозначно связанные изменения.
- В полностью чистом репозитории завершать вызов с сообщением об отсутствии изменений без генерации текста, выбора языка, изменения настроек и пустого коммита.
- Выбирать язык по проектной конфигурации или информативной истории Git. После автоматического определения сначала показывать сообщение, затем явно предлагать сохранить язык или выбрать другой; повторять предложение при последующих вызовах без настройки.
- Сохранять явный выбор в версионируемом `.agents/commit-config.json` и поддержать смену языка проекта.
- При недоступной локали предлагать установленный язык или создание английского шаблона в `.agents/commitlingo/locales/`; допускать новую локаль к выбору после явной проверки, затем предлагать PR в CommitLingo.
- Следовать проектным правилам ссылок на задачи; без них использовать `Refs: ...`, закрывающую ссылку — только при явном намерении закрыть задачу.
- Подготовить автоматические проверки файлов в CI и воспроизводимые ручные сценарии в Codex, оценивающие смысл, грамматику и разрешённые действия без требования точного совпадения текста или обязательного API-ключа.
- Реализовать `npx commitlingo` как npm-обёртку над Skills CLI с фиксированной версией зависимости. Установка локальная по умолчанию, глобальная для Codex — с `--global`.
- Добавить `npx commitlingo update` с той же областью действия, обновляющий только CommitLingo и сохраняющий проектные настройки, пользовательские локали и реестр проверки.
- Распространять согласованные версии npm-пакета и скилла через стабильные релизы с привязкой к Git SHA; обновлять до последнего стабильного релиза без автоматической установки предварительных версий.

## Capabilities

### New Capabilities

- `commit-messages`: содержательная генерация Conventional Commits, проектные соглашения, локализованный текст, валидация и ссылки на задачи.
- `commit-execution`: разграничение генерации и выполнения коммита, выбор изменений и уточнение неоднозначного состава.
- `project-locale`: выбор, предложение сохранения и смена общего языка репозитория.
- `locale-authoring`: создание, проверка и использование проектных локалей, предложение внести их в upstream.
- `skill-installation`: локальная и глобальная установка для Codex, отдельное обновление и воспроизводимые стабильные релизы с сохранением пользовательских данных.

### Modified Capabilities

Нет: существующих спецификаций в проекте пока нет.

## Impact

Планируются `skills/commitlingo/SKILL.md`, локали, атрибуция, npm-обёртка, документация и проверки в CI. Skills CLI становится фиксированной зависимостью установщика; при введении JavaScript обязательна настройка ESLint/Prettier командой пользователя. В потребляющих репозиториях сохраняются проектная конфигурация и пользовательские локали независимо от области установки. Первичная среда — Codex; поддержка остальных агентов, фактическая публикация пакета и автоматическая отправка PR не входят в этот шаг планирования.
