## Grammar rules

Описывай уже завершённый результат изменения, а не задачу на будущее.
Предпочитай естественные краткие страдательные причастия: «добавлена»,
«исправлено», «удалены», «изменён». Согласовывай форму с существительным.
Другие результативные конструкции допустимы, если они точны и естественны.
Не своди правило к механической подстановке прошедшего времени и не переноси
английский imperative в русский инфинитив: «добавить» — формулировка задачи.

Описание обычно начинается со строчной буквы и не заканчивается точкой;
собственные имена и идентификаторы сохраняют регистр. Учитывай ограничения
проекта. Формулируй результат конкретно, без «разных исправлений» и канцелярита.
Body на русском поясняет причины, результат и миграцию, а не план действий.
После `BREAKING CHANGE:` опиши несовместимость и необходимые шаги перехода
по-русски. Служебные type, scope, `BREAKING CHANGE`, `Refs`, `Closes`,
идентификаторы задач, имена кода и URL сохраняются без перевода.

## Good examples

```text
feat(auth): добавлена авторизация через GitHub
fix(parser): исправлена обработка пустого тела коммита
perf(cache): уменьшено число обращений к диску
refactor(config): выделена загрузка настроек
docs: уточнены правила выбора языка
build(deps): обновлены зависимости сборки
feat(cli)!: повышена минимальная версия Node.js

BREAKING CHANGE: требуется Node.js 22.20 или новее; обновите среду выполнения.
```

## Bad examples

- `feat(auth): добавить авторизацию` описывает будущую задачу.
  Исправление: `feat(auth): добавлена авторизация`.
- `fix: исправлена падение` нарушает согласование.
  Исправление: `fix: исправлено падение при пустом вводе`.
- `chore: разные изменения` скрывает смысл и неточно выбирает тип.
  Для исправления ошибки: `fix(auth): исправлено обновление токена`.
